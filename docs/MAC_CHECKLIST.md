# 맥 실기기 점검표 (M3 Pro 18GB 기준)

개발 환경(리눅스)에서는 시연용 엔진으로 흐름만 확인했습니다. 실제 맥에서 처음 한 번 아래 순서로 확인하고, 결과가 "정상"과 다르면 오른쪽 칸대로 조정하세요. 설정은 프로젝트 폴더의 `.env`에 적고 서버를 다시 켜면 적용됩니다.

## 1. 자동 점검 (5분)

```bash
cd backend && .venv/bin/python -m scribe.selftest --compare
```

macOS의 한국어 목소리(Yuna)로 문장을 만들어 받아 적고, 속도와 글자 오류율(CER)을 잽니다. Yuna가 없으면 시스템 설정 → 손쉬운 사용 → 읽기 및 말하기 → 시스템 목소리 → 목소리 관리에서 받습니다.

| 항목 | 정상 | 다르면 |
|---|---|---|
| 실시간 속도 | 실제 시간의 5배 이상, 문장 하나 0.5초 이하 | 더 가벼운 모델: `SCRIBE_LIVE_MODEL=moona3k/mlx-qwen3-asr-0.6b-4bit` |
| 원본 속도 | 1시간 녹음 → 15분 안팎 | 다른 무거운 앱을 끄고 다시 측정 |
| 원본 CER (합성 음성) | 5% 이하 | 용어집(설정 → 자주 나오는 용어·이름)에 이름·용어 추가 |
| 8bit와 fp16 차이 | 0.5%p 이하 → 8bit 유지 | `SCRIBE_PRECISION=fp16` (모델 약 8.4GB, 메모리 더 씀) |
| 화자 구분 | 1명 (한 목소리) | `HF_TOKEN`, pyannote 약관 동의 확인 |

내 목소리로도 확인하려면: 1분쯤 아무 글이나 읽으며 녹음한 파일과 그 글을 넣습니다.

```bash
.venv/bin/python -m scribe.selftest --audio 내녹음.m4a --text "읽은 글 전체"
```

## 2. 회의실에서 직접 (20분)

| # | 확인할 것 | 어떻게 | 정상 | 다르면 |
|---|---|---|---|---|
| 1 | 마이크 고르기 | 녹음 시작 옆 마이크 이름을 누르고 말해 보기 | 막대가 움직이고 "잘 들려요" | 다른 마이크 선택, 시스템 설정 → 사운드 → 입력 음량 |
| 2 | 자막 지연 | 한 문장 말하고 화면 보기 | 1~2초 안에 문장이 뜸 | 1번 표의 실시간 속도 확인 |
| 3 | 말소리 감지 | 2분 동안 평소처럼 대화 | 말할 때 마이크 아이콘이 은은하게 빛남 | 너무 둔하면 `frontend/src/hooks/recorder.ts`의 SpeechMeter 기준(0.015, 바닥 소음의 3.5배)을 낮춤 |
| 4 | "쉬는 시간인가요?" | 3분 동안 조용히 있기 | 3분 뒤 한 번만, 15초 뒤 표시줄로 접힘 | 대화 중에 뜨면 설정에서 5분으로 |
| 5 | 일시정지 중 말소리 | 일시정지 후 1분 동안 말하기 | 30초가 지난 뒤 한 번만 알림 | 알림이 너무 잦거나 늦으면 같은 파일의 `pausedGrace` |
| 6 | 마이크 빼앗김 | 녹음 중 Zoom 등에서 같은 마이크 사용 | 30초 뒤 아이콘이 주황, 1분 뒤 경고 | - |
| 7 | 블루투스 | 에어팟을 고르기 | "통화 음질로 바뀌어…" 한 줄 | - |
| 8 | 잠자기 방지 | 녹음 중 터미널에서 `pmset -g assertions \| grep -i caffeinate` | `PreventUserIdleSystemSleep` 항목이 보임 | `which caffeinate` 확인 |
| 9 | 덮개 닫기 | 녹음 중 덮개를 30초 닫았다 열기 | 기록에 "쉬는 시간" 구분선 | - |
| 10 | 서버 끊김 | 녹음 중 `./run.sh` 창에서 Ctrl+C 후 다시 실행 | 아이콘만 잠깐, 다시 연결 뒤 끊긴 동안 소리도 저장(구분선 없음) | - |
| 11 | 실시간 화자 | 참여자 2~3명을 넣고 5분 회의 | 1~2분 안에 "화자 A/B"로 나뉘고, 한 번 고르면 같은 사람 문장이 대부분 맞게 바뀜 | 다른 사람을 같은 화자로 자주 묶으면 `SCRIBE_LIVE_SPK_SAME=0.6`, 같은 사람을 자꾸 새 화자로 나누면 `0.4` |
| 12 | 끊겼다 이어 말하기 | "검토부터 시작하겠는데… (1초 쉼) …예산은요" 처럼 말하기 | 한 문장(한 단락)으로 이어짐 | 너무 오래 붙으면 `backend/scribe/live.py`의 `continue_silence_s`(1.1초)를 낮춤 |
| 13 | 배터리 | 전원을 뽑고 녹음, 녹음 표시줄을 눌러 보기 | 상태에 "배터리 절약" | - |

## 3. 녹음을 마친 뒤

| # | 확인할 것 | 정상 | 다르면 |
|---|---|---|---|
| 1 | 30분 회의 원본 만들기 | 약 8분, 활동 모니터의 메모리 압력이 초록 | 노랑·빨강이면 `SCRIBE_PRECISION=8bit` 확인, 크롬 탭 줄이기 |
| 2 | 화자 수 | 실제 인원과 같음 | 원본 다시 만들기 전에 설정할 수 있게 하려면 알려 주세요 |
| 3 | 목소리 기억 | 화자에 이름을 붙이고 다음 회의 원본에서 "이름?" 제안이 뜸 | 제안이 안 뜨면 `SCRIBE_VOICE_MATCH=0.45`, 엉뚱하면 `0.65` |
| 4 | m4a로 줄이기 | `SCRIBE_COMPRESS_AFTER_H=0`으로 켜면 1~2분 안에 `~/MeetingScribe/meetings/<id>/audio.m4a` | 재생·이어서 녹음이 그대로 되는지 확인 |
| 5 | 자동 실행 | `scripts/launchagent.sh install` 후 다시 로그인 → 주소가 바로 열림 | `scripts/launchagent.sh status`, `~/MeetingScribe/server.log` |
| 6 | 백업 | 설정 → 전체 백업 내려받기 | zip 안에 scribe.db, meetings, 회의록 폴더 |
